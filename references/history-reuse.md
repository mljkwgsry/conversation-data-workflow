# 原目录接续与历史复用

适用于包含history或layout_mode=legacy的配置。先读catalog_path和archive_pointer，仅定位所选场景需要的产物，不一次载入全部请求响应。

1. 原件存在时核对路径和SHA-256，直接读取原件。ZIP只是保留原件的备份，不先解压、不搬家、不重新生成。归档complete仅表示快照完整，不表示历史评测通过。
2. 原件缺失时按archive/member解压到独立恢复目录，核验hash后引用，不覆盖同名已有文件。多个不同hash版本不能合并；无法选定时列出候选。
3. 输入按完整项目值隔离。同一目录可能容纳多个项目，新文件不能直接追加到名单标注输入。缺少对应名单时可分析对话，不能用其他项目名单计算业务结果。
4. 按scenes[].outputs沿用原目标目录，新批次或报告使用唯一运行ID。标注默认在原分组目录下保存副本；原位更新仍须有授权并完成备份、校验。
5. 沿用原测试集hash。名单按原规则合并去重；身份映射复用前核验同组数据源及完整三元组，不能仅凭有文件就跳过内容核验。历史Yes证据仍须可追溯。
6. Prompt有正文、中文对照、修订前备份、线上协商等分支。按用户指定版本与分支、版本清单和hash选择；不能按文件时间或最高版本选择父版本。prompt_candidates仅是候选，不是当前生效版本。
7. 单轮与多轮历史分开。assistant_direct用户由代理直接扮演，不能与模型生成用户台词的轨迹视为同条件。manifest未声明模式时读取历史实际配置，不猜默认模式。通用多轮规范与历史模式不同，须明确差异；不能冒充同条件新运行。
8. 恢复评测仍核验Prompt、测试集、角色、夹具、采样、模型与量表。未指定candidate/parent或预算时，先完成历史定位和可独立的数据分析，网络阶段保持未执行。

ZIP成员保留相对目录及SHA-256清单，打包后逐项回读验证，确认原件未变；变化中文件单列partial。保留原件会增加压缩包占用，不宣称释放了原磁盘空间。

真实通话、名单、身份映射、请求响应和本地配置只保存在本地归档。公开仓库仅维护通用规则及脱敏模板，历史归档不进入公开分享包。
