# annotate：名单事件标注

前置：calls、outcomes、outcome.membership_basis、字段映射、身份规则。标注代表“在指定名单中匹配”，不自动代表某通电话促成业务事件。

## 名单与身份

- 优先显式文件；用户仅给目录时发现同组原始名单并冻结文件列表，覆盖窗口重叠时按配置三元组去重，保留来源；不只取最新名单漏掉其他事件。不要根据未知状态码删行。
- direct exact_id：用已核实的call_key/outcome_key精确关联，记录冲突与空键；不查询手机号。
- phone：若名单有已核实的客户电话列可直接映射；否则进入同一数据源的**语音外呼子任务表**，用Token/批次任务ID/子任务ID共同精确定位。不能使用更新记录ID替代子任务ID。
- 打开唯一匹配记录详情，在subTaskInfo核实客户本人电话字段。不能预设字段名或使用联系人/主叫号。缓存键包含数据源、场景、完整三元组及字段路径；缺失、掩码、歧义、多候选记unknown。
- ng_e164仅在country=NG下接受10位本地、0+10位、234+10位、+234+10位、00234+10位且格式有效的号码，归一为234+10位。其他地区不用此规则。保留原值，不模糊匹配、补数字、截尾或匹配空值。

## 写入与复跑

1. calls含项目字段时核验项目完整值；不含项目字段时以明确的分组来源清单证明归属，没有归属证据则暂缓该组匹配。建立有证据的事件客户集合。命中用户的全部通话标positive；未命中仅在映射完整且目标身份可靠时标negative，含义是“当前名单未匹配”，并非已证明业务未发生。
2. 存在未完成映射时，不给可能受影响记录正式标No；保留带unknown的草稿与待核对清单。若正式格式要求Yes/No，受影响组暂不发布正式结果。独立完整组可交付。
3. 默认输出新标注副本到运行目录。用户明确要求原地更新时，先备份并验证hash，再临时写入校验后原子替换。保持原行顺序、原列字符串值、编码/BOM；更新已存在的标注列，不重复追加。不要去重或删掉通话行。
4. 复跑时合并有来源的历史positive证据，缩小名单窗口不能默默把历史Yes降No；窗口不兼容时标注各自语义/窗口，冲突待核对。不要无来源地永久保留旧Yes。
5. 逐行核验原始值不变、行数不变、标注列唯一、同一用户所有记录一致、无跨组命中。事件客户找不到通话只列“无对应通话”，不补造通话。

输出：标注CSV、来源hash、身份映射/查询覆盖、unknown明细、每组任务数/唯一客户数/positive与negative通话数、名单与通话窗口。身份映射本地保存，聊天与报告仅脱敏汇总。
