# analyze：数据质量、业务与对话诊断

前置：calls和字段映射。标注与名单可选；缺失时仍完成数据质量和对话分析，业务结果指标标不可计算。

1. 核验编码、列名、ASR结构、时间范围、hash和空值。通话按配置call_id优先、id回退去重；两者没有时用文件+记录号追溯不猜合并。同键异文单列冲突；标注阶段不去重，分析阶段单独说明去重口径。
2. 客户按组内已核实身份键计数，未知身份从客户率分母排除并单列。一个客户5通均命中，应为1客户/5通命中；跨组重叠不直接相加为独立客户。复核标注证据和映射完整性，不依摘要complete字段作结论。
3. 主要名单指标=命中客户/可判定有效身份客户；另报命中通话/去重通话。声明名单窗口、可判定分母与缺失。只有录音/接听子集时，不计算全量接通率；无真实事件时间/金额与观察窗，不计算通话后转化、ROI、因果提升。更新时间不是事件发生时间。
4. 根据analysis.dimensions和业务配置分层，如日期、交互次数、时长、产品类型；催收才按金额/逾期/减免分析。结构化字段优先；ASR提及值要附原文及提取覆盖率，不能称已核验账单/预约事实。缺失独立一层。
5. 按配置role_labels解析用户与客服；区分固定开场与动态回应。业务场景、沟通问题和行为规则都须依本场景定义，不向预约业务移植已付款/罚息/承诺还款标签。规则命中是筛查，不能冒充语义质检通过率。
6. 每组复核最多8条或配置的更大数量完整上下文（不足时全部），覆盖命中/未命中/未知和主要失败类型。案例给脱敏摘录、源文件hash、记录号/call_id。案例抽样不能估计全量发生率。
7. 对比例报告n、分子、分母、缺失与适用范围；默认n<30或阳性<5标小样本，可给Wilson区间，但不能用区间修正漏标。跨组差异仅描述。

每组HTML：结论及缺口 → 数据范围/质量 → 业务分层 → 对话表现/案例 → 优先改动与测试 → 来源方法。另输出metrics.json、cases.json、字段提取规则、coverage.json。
每条建议包含“证据→问题→具体Prompt修改→测试场景→验收门槛→业务/平台边界”，优先证据最强2—3项。原始数据不修改。无数据组记录原因，无报告内容可造。
