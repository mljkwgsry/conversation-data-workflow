# analyze：数据质量、业务与对话诊断

前置按模式区分：真实外呼为calls和字段映射；多轮为完整轨迹及运行/业务事实快照。标注与名单可选；缺失时仍完成数据质量和对话分析，业务结果指标标不可计算。

催收场景生成分析报告前，读取[催收数据分析维度准则表](collection-analysis-criteria.md)，按数据和有／无／未知减免模式选择适用维度。该表只指导报告分析与Prompt迭代建议，必须按同表固定口径评分，不额外生成场景包；非催收业务不加载，产物以用户本次要求为准。

多轮输入：使用本次上游multiturn交接，或配置 `inputs.multiturn_archive` 指向既有manifest/analysis-input.json；也可配置 `analysis.input_type=multiturn` 并沿用 `evaluation.archive`。无需calls、ASR映射或名单。核对角色、版本、上下文、真实发生轮次、停止原因和失败，按统一量表逐轮评分、取整段最低分并对比版本；不调用模型补写轨迹。OKash读取数据分析skill的multiturn-analysis.md，诊断与评分均由该skill执行。以下1—7为真实CSV模式。

1. 核验编码、列名、ASR结构、时间范围、hash和空值。通话按配置call_id优先、id回退去重；两者没有时用文件+记录号追溯不猜合并。同键异文单列冲突；标注阶段不去重，分析阶段单独说明去重口径。
2. 客户按组内已核实身份键计数，未知身份从客户率分母排除并单列。一个客户5通均命中，应为1客户/5通命中；跨组重叠不直接相加为独立客户。复核标注证据和映射完整性，不依摘要complete字段作结论。
3. 主要名单指标=命中客户/可判定有效身份客户；另报命中通话/去重通话。声明名单窗口、可判定分母与缺失。只有录音/接听子集时，不计算全量接通率；无真实事件时间/金额与观察窗，不计算通话后转化、ROI、因果提升。更新时间不是事件发生时间。
4. 根据analysis.dimensions和业务配置分层，如日期、交互次数、时长、产品类型；催收才按金额/逾期/减免分析。结构化字段优先；ASR提及值要附原文及提取覆盖率，不能称已核验账单/预约事实。缺失独立一层。
5. 按配置role_labels解析用户与客服；区分固定开场与动态回应。业务场景、沟通问题和行为规则都须依本场景定义，不向预约业务移植已付款/罚息/承诺还款标签。规则命中是筛查，不能冒充语义质检通过率。
6. 每组复核最多8条或配置的更大数量完整上下文（不足时全部），覆盖命中/未命中/未知和主要失败类型。案例给脱敏摘录、源文件hash、记录号/call_id。案例抽样不能估计全量发生率。
7. 对比例报告n、分子、分母、缺失与适用范围；默认n<30或阳性<5标小样本，可给Wilson区间，但不能用区间修正漏标。跨组差异仅描述。

每组HTML：结论及缺口 → 数据范围/质量 → 业务分层 → 对话表现/案例 → 优先改动与测试 → 来源方法。另输出metrics.json、cases.json、字段提取规则、coverage.json。
每条建议包含“证据→问题→具体Prompt修改→测试场景→验收门槛→业务/平台边界”，优先证据最强2—3项。原始数据不修改。无数据组记录原因，无报告内容可造。


催收报告的主评分必须遵循[统一分析与评分准则](collection-analysis-criteria.md)“固定报告评分口径”；旧六维只作诊断。逐轮0–2分、整段最低分，分列完整处理/内容完整/阻断，按同案例比较；历史/线上数据仅在复核范围评分并与回款分开。

## 多轮分析交接合同

| 输入证据 | 分析职责 | 输出 |
|---|---|---|
| 原始请求响应与完整用户/客服轨迹 | 核对实际发生轮次、失败、截断、角色状态和上下文完整性 | 有效性清单及排除原因；技术成功不等于质量通过 |
| suite/persona、可见前缀、Prompt与业务夹具快照 | 分离角色私有信息与客服可见事实，检查版本配对和条件差异 | 可比性说明、来源hash与覆盖缺口 |
| 按case/version/repeat/turn定位的实际台词 | 逐轮语义评分与理由、原话证据；真实回放前缀不计为新生成表现 | 逐轮评分CSV、会话评分及分场景统计 |
| 版本成对轨迹 | 同案例比较改善/持平/退步与新增问题；重复轨迹不当独立客户 | 独立组别HTML、版本比较及复测建议 |

催收主评分读取collection-analysis-criteria.md；其他业务使用evaluation.rubric及rubric_version。每份报告说明评分范围和适用分母，缺失与不确定独立列出，保留完整对话的追溯链接。当前代理参与了角色生成时明确非盲评。只重评时不重新调用客服模型，不补造未发生的后续对话。

角色扮演产物到原multiturn.run_dir，评分与报告到所选场景analyze输出目录；legacy配置已有multiturn.report_dir可作为多轮报告路径兼容回退，由analyze负责写入。只读原始轨迹；新分析产物保留rubric_version，旧报告备份或另建重评批次。
