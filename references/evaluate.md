# evaluate：单轮生成与历史重评

读取gateway.md。mode=generate才调用网络；mode=rejudge仅读取archive已有响应，在新评分批次产出结果，不重发请求、不修改旧报告。

generate前置：同场景完整baseline/candidate、固定测试CSV、业务fixture与来源、rubric_version和可判定标准。可仅评候选，但不可宣称双版本改善。版本按整数段解析V2.10>V2.9，优先显式路径/hash，不按修改时间选版本。

rejudge前置仅为可读取的历史输出索引archive、rubric及rubric_version；不要求当前Prompt文件、当前API文档或网络发现。核对历史输出所含场景、输入和业务证据；缺少历史Prompt/hash或夹具时限制可比性，将依赖缺失事实的评分标为不可判定，不补造、不强迫重跑。重新判读原输出并另存新评分批次。以下1—4是generate流程，5—6及输出合同适用于两种模式。

1. 冻结原始Prompt、TXT提取快照、测试、夹具、生成配置和量表hash。RTF用textutil提取并核验；TXT/RTF一致算同版本。硬编码品牌与场景冲突须解决，不擅自改写被测Prompt。
2. 提取实际模板变量，保留拼写/大小写；字面量替换，不执行模板表达式。缺少必需变量阻塞对应版本。共同变量语义相同，新版不能得到基线没有的额外事实。金额等模拟夹具标synthetic_fixture，不能伪装正式政策。
3. 单条独立messages=[system完整渲染Prompt,user原始测试话术]，不自行添加开场/历史/工具。测试ID只在场景内唯一，联合键带scene_id。
4. 按网关规范冒烟、并发、落盘、恢复。复用已有基线前核验模型来源、测试/Prompt/参数/夹具/上下文hash及量表一致；实际缺口列明，不因入口名不同自动否定，也不把OKash历史模型同源确认推广到新业务。
5. 每条结果保留原输出、判定、依据、不可判定原因和审阅方式。建议通用维度：诉求理解、问题处理、计划完整性、路径可执行性、事实与权限、沟通接受度；场景可替换，先固定定义与门槛。无逐条语义复核不得报全量语义通过率，API成功率不是业务效果。
6. 同一业务规则和共同可判定分母比较，分别展示改善/退步/持平/未知；源自模型、政策、夹具或测试集差异的影响独立列出。模拟表现不能当线上收益。

输出每场景HTML、任务索引、逐例评分、按轮次CSV与运行清单。CSV基础列保持`测试组ID,轮次,客户话术,AI回复,状态,错误`；追加scene_id、版本、requestId、attempt、HTTP/finish_reason、时间、模型、usage、原始文件路径。单轮轮次=1，重试不是新轮次。usage缺失留空。
