# iterate：证据驱动Prompt候选

前置：明确parent_path、target_version、对应场景报告或评测结果、业务政策、变量/输出约定。先读完整父版本和证据，不能只把报告补丁叠加到矛盾旧规则末尾。

1. 优先用户指定父版本及其hash；报告应能关联实际被测Prompt，配置ID/修改时间不能证明曝光版本。无法归因时可整理候选改动并注明限制，不宣称某版本测试驱动升级。
2. 按场景优先改2—3个最有证据的问题，逐项记录“来源章节/案例→问题→替换位置→期望行为→回归测试→验收标准”。共性修复需注明跨组依据，不迁移业务权限。
3. 保留品牌、语言、模板变量拼写/类型/语义、结束标记与输出结构。新变量注明供值方及缺失降级，未经对接不得假装已存在工具。删除角色/示例/结尾中的冲突规则。
4. 只使用policy有依据的权限：催收减免以合格费用为基数，不等于总额折扣；预约/售后业务使用各自政策，不继承催收话术。意向/客户自述不是核实到账或预约成功。平台能力缺口单列，不用Prompt伪造能力。
5. 保留父版本和全部历史文件；版本按整数段递增。目标版本同hash可复用，异hash另存明确候选修订目录，不覆盖或偷偷跳号。回滚只建立指向旧hash的记录。
6. 输出完整TXT，若要求兼容RTF则生成并回读核验相同；diff、HTML修改说明、manifest、回归用例一并交付。manifest记录scene、父/新版本和hash、证据来源、变量变化、业务限制、状态；未回放为not_run。回归用例含输入、预期、判定规则、实际结果null。
7. 静态检查变量与权限/冲突、历史hash未变；模型评测属于evaluate/multiturn，只有被用户包含在本次范围才运行。候选生成完成不等于模型通过、上线或优于旧版本。
