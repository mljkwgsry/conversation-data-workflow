# extract：原始数据提取

前置：本次场景、data_source、time_window、project_value（通话）或list_token（名单）、data_dir。用户可以只导出calls或outcomes，将所选类型记入清单。配置 `extract_kinds` 控制类型，默认两类；单类不要求另一类筛选值。

1. 复用已登录浏览器；当前本机Edge曾验证能下载，可优先使用。按当前UI状态定位，不依赖历史元素索引。进入配置Buildstore地址及指定数据源；不要将旧尼日利亚数据源带入新产品。
2. calls：Directus「外呼底层表」。清除残留筛选，call_log包含完整项目字符串并紧跟JSON结束双引号，voice_url不是空，二者AND。导出后解析call_log里的配置项目字段作完整相等核验，防止`:3`匹配`:30`。voice_url非空仅表示本次录音记录筛选口径，不能单凭此证明接通。
3. outcomes：Directus「语音外呼子任务更新表」（可能显示「语音通话子任务更新记录」）。清除关键词、批次/子任务及高级筛选残留，按完整Token查询。不猜状态码；是否代表已还款、已预约等，由`outcome.membership_basis`声明。无依据时仍可导出“更新记录”，不能输出带业务成功含义的标签。
4. 核实页面时间范围、时区、总条数与显示列；calls至少包含项目、录音、时间和后续所需字段，名单保留原显示列。点击“导出显示列”导出全部匹配记录。识别本次新下载，文件大小稳定、可完整解析才算完成。
5. CSV按记录计数，核对页面总数、唯一项目/Token、录音非空和时间覆盖。动态新增造成数量差异须说明。发现混组/截断需修正筛选再导出，不能删掉错误行冒充原始导出。大批次可按不重叠时间拆分，记录每批及去重依据。
6. 保留原始文件字节，移动前后SHA-256一致；命名包含类型和有证据的查询/记录覆盖日期，同名不同内容追加运行ID。不擅自转换未知时区；只知道记录最小/最大日期就注明“记录覆盖”，不冒充查询边界。
7. 页面核实零记录后可保存明确标识的仅表头占位文件；查询失败不得当零。输出每组/类型清单：筛选、查询窗、记录窗、行数、hash、路径、来源与异常。失败组标partial/blocked，不虚构全组完整。
